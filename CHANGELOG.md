# История изменений

## [0.18.1] - 2026-11-10

- Локальный мост `app` подключается к официальному Path of Building под Wine на Linux. Папка сборок открытого PoB возвращается путём Linux.
- `pob_list_characters` и `pob_get_character` используют действующий вход в оригинальном PoB на Windows и Linux. Мост передаёт сведения о персонаже без учётных данных.
- `pob_import_character` загружает экипировку, камни умений, дерево и самоцветы штатными функциями PoB в отдельной сессии Lua.

## [0.18.0] - 2026-11-10

- Публикация остановилась на проверке регистра пути macOS. Возможности вошли в v0.18.1, где тест сравнивает сам каталог.

## [0.17.0] - 2026-11-10

- Режим `editor` передаёт правки дерева, экипировки и умений в открытую сборку PoB II через локальное соединение. Пересчёт в Lua, сохранение и Undo/Redo выполняет редактор.
- Подключение требует разрешения в PoB II. После изменения сборки клиент получает свежий отчёт через `pob_check_build` перед следующей правкой.

## [0.16.0] - 2026-11-09

- Подбор и редактирование поддержек умений от предметов через `pob_gem_supports` и `pob_update_skill_group`. Умение и уровень задаёт источник. PoB 0.23.1 хранит поддержки в группе слота экипировки, новые ревизии PoB — в группе самого умения.

## [0.15.0] - 2026-11-06

- `pob_compare_item` примеряет предмет штатным `GetMiscCalculator` без изменения XML и ревизии. Таблица «Было → Стало», формат значений и смысл изменений берутся из `FormatStat`/`CompareStatList`; учтены выбранный набор оружия и показатели приспешника. Отсутствующее значение не заменяется нулём.
- `pob_equip_item` принимает `expectedRevision` из примерки: устаревшее применение отклоняется до изменения состояния и процедуры отката.
- `pob_trade_catalog` читает совместимые базы, характеристики, варианты и валюты исходного PoB. `pob_trade_search` собирает ссылку для браузера по лиге, бюджету и фильтрам; категорию и кодирование пути определяют штатные методы PoB. Эти операции не обращаются к торговому API и не загружают объявления.

## [0.14.0] - 2026-11-06

- `pob_gem_tooltip` возвращает описание умения или поддержки из исходного `Classes/GemTooltip`. Установленный камень выбирается по группе и `sourceIndex`, с его реальными уровнем, качеством и контекстом; каталог и черновик принимают ID, уровень и качество.
- Чтение описания не меняет XML, расчёт и ревизию сборки. Неверные ссылки и смешение двух способов выбора отклоняются. Цвета и разделители исходного PoB сохраняются для оформления внешним интерфейсом.

## [0.13.0] - 2026-11-06

- `pob_inspect_item` разбирает текст или сохранённый предмет исходным `Item` и возвращает описание `ItemsTab:AddItemTooltip`, требования, нераспознанные строки и совместимые слоты без изменения XML и ревизии. Подсказки о клавишах исходного окна не передаются.
- `pob_equip_item` надевает, заменяет и снимает предмет через исходные методы слота. Снятый предмет остаётся в списке сборки; неверная замена сохраняет прежнее состояние.
- `pob_select_weapon_set` переключает I/II исходными кнопками PoB. Отчёт включает выбранный набор, видимость и принадлежность слотов; текст предметов приведён к исходному каноническому `BuildRaw`, чтобы повторный импорт не менял представление.

## [0.12.0] - 2026-11-06

- `pob_delete_skill_group` удаляет выбранную группу штатным `SkillListControl.OnSelDelete`, включая обновление выбранного основного умения. API исполняет только подтверждение этой явно запрошенной операции; обработчик диалогов сразу восстанавливается. Группы от экипированных предметов защищены от удаления.
- Удаление поддерживает общий протокол ревизий и восстановление XML при ошибке. Последнюю группу также можно удалить; исходный PoB пересчитывает пустой список.

## [0.11.0] - 2026-11-06

- `pob_update_skill_group` изменяет выбранную группу исходным `SkillsTab`, сохраняя её слот, состояние, выбор частей и дополнительные параметры сохранённых камней. `sourceIndex` из отчёта позволяет переставлять камни без потери их настроек; неверная ссылка отклоняется с восстановлением XML.
- В отчёт добавлены `customLabel`, `source` группы и `sourceIndex` камня. Проверка совместимости принимает `groupId`, чтобы пробное редактирование сохраняло исходный контекст группы и не меняло текущую сборку.

## [0.10.0] - 2026-11-06

- Оригинальные иконки камней: `pob_gem_icons` принимает ID из Lua и возвращает изображения PNG/WebP. Активные умения читаются из ресурсов PoB; отсутствующие в нём изображения поддержек GGG — из закреплённого каталога PoE2DB с SHA-256 и локальным кешем. Игровые характеристики из внешнего источника не загружаются.
- `pob_gem_supports` проверяет черновик в отдельной сессии Lua штатным `calcLib.canGrantedEffectSupportActiveSkill`, как каталог PoB. Первая позиция — умение, остальные — поддержки. Текущий XML, ревизия и окно PoB не изменяются.
- В каталоге исправлен признак поддержки: используется `gem.grantedEffect.support`; добавлен исходный `variantId`. Новые методы доступны на Windows, Linux и macOS.

## [0.9.1] - 2026-11-05

- Каталог включает исходный режим «Урон / защита» (`OffenceDefence`) и его оригинальную общую тепловую карту. Как и в PoB, список числового отчёта доступен для отдельных показателей.
- Геометрия дерева передаёт исходный `isAttribute`, в том числе для уже назначенных узлов. Переключение варианта через `allocate` сохраняет активный путь; добавлена проверка настоящим Lua.


## [0.9.0] - 2026-11-05

- Поэтапный поиск влияния узлов по характеристике и расстоянию через оригинальные `CalcsTab:PowerBuilder` и `TreeTab:BuildPowerReportList`.
- Публичный `pob_node_power`: каталог, запуск, прогресс, отмена, готовая тепловая карта и список с исходными значениями/очками/влиянием на очко.
- Отчёт не меняет XML и ревизию; изменение сборки делает незавершённый расчёт недействительным. Доступен в отдельной сессии `engine`.


## [0.8.0] - 2026-11-05

- `pob_tree_hover`: готовая оригинальная подсветка пути или зависимых узлов и подсказка `AddNodeTooltip` с расчётными изменениями. Сборка и ревизия не меняются.
- Передаётся только дополнительный слой подсветки, без повторной отправки полного дерева. Ресурсы слоя доступны через прежние токены `pob_tree_textures`.
- Подсказки отделены от сцены, чтобы интерфейс Flutter показывал сведения при наведении без постоянных подписей.

## [0.7.0] - 2026-11-05

- Готовая сцена оригинального `PassiveTreeView`: `pob_get_tree(includeScene=true)` передаёт упорядоченные четырёхугольники с координатами, UV, цветом и режимом смешивания. Сохранены оригинальные дуги, рамки, фоны и портреты. Игровые правила и построение сцены остаются в Lua.
- `pob_tree_textures` читает ресурс только по токену выданной сцены и возвращает PNG RGBA. Произвольные файлы недоступны.
- Ресурсы DDS BC7 декодируются средствами Windows либо закреплённым bcdec на Linux/macOS. Лицензия включена в native-архивы. Проверка проходит по всем текстурам настоящей сцены.

## [0.6.0] - 2026-11-05

- `pob_tree_icons`: оригинальные иконки текущего дерева из Lua, до 32 имён за запрос, PNG RGBA с прозрачностью. Все 524 иконки закреплённого дерева проверяются настоящим Lua. Имена не позволяют читать посторонние файлы.
- Переносимое декодирование DDS BC1 без Direct3D/GDI; Linux/macOS native-архивы включают закреплённый Zstandard 1.5.7 с лицензией BSD.

## [0.5.2] - 2026-11-05

- Компактное настоящее дерево Lua через `pob_get_tree`: узлы, связи, выбранные состояния, версия и очки для собственного интерфейса Flutter.
- Проверка готового Windows ZIP проверяет наличие инструмента геометрии без устаревшего ограничения числа инструментов. Тег 0.5.1 также был остановлен CI до публикации.

## [0.5.1] - 2026-11-05

- Выпущен публичный `pob_get_tree` с компактной геометрией настоящего дерева Lua для Flutter: узлы, связи, выбранные состояния, версия и очки. Работает без PNG на Windows/Linux/macOS.
- Проверки обнаружения MCP учитывают новый инструмент. Тег 0.5.0 был остановлен CI до публикации пакетов.

## [0.5.0] - 2026-11-05

- Публичный `pob_get_tree` возвращает компактную геометрию настоящего дерева из Lua: координаты, связи, типы и имена узлов, выбранные узлы, версию и строку очков. Работает без PNG и Direct3D на всех платформах `engine`.
- Геометрия предназначена для собственного интерфейса; игровые действия и проверка допустимости остаются в Lua.

## [0.4.1] - 2026-11-05

- Диагностика `engine` возвращает фактическую платформу: `windows-engine`, `linux-engine` или `macos-engine`; историческая метка Windows больше не показывается на других ОС.
- Исправлен порядок аргументов в инструкции запуска `doctor` на Linux/macOS.

## [0.4.0] - 2026-11-05

### Добавлено

- Настоящий Lua в режиме `engine` на Linux x64 и macOS Apple Silicon. Исходные игровые формулы не изменены и не перенесены в Python.
- Отдельные архивы LuaJIT и lua-utf8, собранные из закреплённых ревизий с исходными лицензиями. Установка библиотек в систему не требуется.
- CI запускает диагностику, создание и изменение сборки, расчёты, XML и MCP stdio с исходным PoB на Windows, Linux и macOS.
- Публикация обоих нативных архивов с SHA-256 вместе с wheel и Windows ZIP.

### Ограничения

- PNG-отрисовка через GDI/Direct3D и режим управления оригинальным окном PoB остаются возможностями Windows. Перенос касается отдельных расчётов Lua (`engine`).
- Для Linux/macOS требуется Python 3.11+ соответствующей архитектуры. Архивы: Linux x64 (Ubuntu 22.04+) и macOS arm64 (11+).

## [0.3.0] - 2026-11-05

### Добавлено

- Инструмент `pob_render_image`: PNG сводки, схемы дерева, всех характеристик, предметов, камней, условий расчёта, заметок, предупреждений и полного отчёта. Отдельные предметы и узлы доступны по ID; длинные отчёты разбиваются на страницы.
- Изображения возвращаются блоками MCP `image` в обоих режимах; Windows GDI и кодировщик PNG не требуют дополнительных пакетов. Согласованный снимок Lua сохраняет исходную сборку и ревизию.
- Дерево воспроизводит оригинальный `PassiveTreeView:Draw` через Direct3D 11 WARP: DDS BC1/BC7 и PNG, пропорциональный масштаб иконок, рамки, фоны, свечение и дуги. Добавлен `zoom`; подписи по умолчанию скрыты. Служебные связи с восхождением не рисуются.
- В режиме `app` изображения дерева формируются по XML в отдельной сессии Lua; ради отрисовки не требуется изменять файлы установленного PoB или обновлять его мост.

### Исправлено

- Режим `app` восстанавливает соединение после закрытия или перезапуска PoB без перезапуска MCP-сервера. Запрос чтения при обрыве повторяется не более одного раза с актуальными адресом, токеном и ревизией.
- Команды изменения при потере ответа не повторяются; следующий запрос использует новое соединение.
- Закрытие соединения после тайм-аута больше не ждёт заблокированный читающий поток.

## [0.2.0] - 2026-11-05

### Добавлено

- Готовый Windows ZIP со встроенным Python: отдельная установка Python, pip и Git для работы с установленным PoB не нужна.
- Автоматический поиск обычной установки PoB по реестру и стандартным каталогам; поддержка portable-каталога и исходного репозитория.
- Режим `app`: чтение и изменение текущей сборки в настоящем окне PoB через локальный Lua-мост.
- Команды установки и удаления моста с резервной копией `Launch.lua`, а также готовая настройка обоих MCP-серверов через `config`.
- Обнаружение ручных правок, проверка ревизии, защита несохранённой сборки при замене и блокировка изменений при открытом диалоге.
- Автоматическая публикация релиза по тегу: проверки, сборка wheel и ZIP, описание из changelog и SHA256SUMS.

### Изменено

- `setup` загружает движок из официального `PathOfBuildingCommunity/PathOfBuilding-PoE2`.
- Режим `engine` использует уже установленный PoB без повторного скачивания движка.
- API совместим с конструкторами классов стабильной PoB 0.23.1 и закреплённой ветки разработки.
- Фоновый процесс использует включённые headless-определения, не читает личные настройки и не записывает файлы установленного PoB.

### Исправлено

- Ошибки создания предметов и чтения подсказок узлов на стабильной версии PoB.
- При откате ошибочной операции сохраняются имя, путь файла и признак несохранённых изменений текущей сборки.
- Отсутствующие в версии PoB заметки узлов возвращают явную ошибку неподдерживаемой операции.

## [0.1.0] - 2026-11-05

- MCP выделен в отдельный устанавливаемый Python-пакет с 13 инструментами.
- Добавлены установка из GitHub, отдельная загрузка движка и диагностика `doctor`.
- Сохранены исходные лицензии и документация API.
- Добавлены проверки настоящего Lua, MCP stdio, импорта и экспорта XML.
