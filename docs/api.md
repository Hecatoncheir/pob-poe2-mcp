# API сборок

MCP stdio и Python API используют исходные классы Lua официального PoB. Режим `engine` создаёт отдельную сессию на файлах установленного приложения, режим `app` работает с текущей сборкой окна через Lua-мост. Установка и настройка клиента описаны в [README](../README.md).

```powershell
python -X utf8 run.py serve --pob-dir C:/Tools/PoB-engine
python -X utf8 run.py serve --mode app
```

Все относительные пути ниже относятся к репозиторию `pob-poe2-mcp`. Игровые данные соответствуют выбранной установке PoB. Для `setup` закреплена ревизия официального репозитория; она не обновляется автоматически до последних данных игры.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `pob_catalog` | Каталоги `classes`, `gems`, `bases`, `slots`, `nodes`, `config`; поиск `query`, страницы `offset`/`limit` до 200 записей. Доступен до создания сборки. |
| `pob_create_build` | `newBuild()`, название, ручной уровень 1–100, `classId` из каталога; заменяет текущую сессию. |
| `pob_import_xml` | Полный XML `PathOfBuilding2`, загрузка и пересчёт. |
| `pob_add_skill_group` | Новая группа с массивом камней: точный `id`, `level`, `quality`, необязательный `enabled`. |
| `pob_add_item` | Исходный игровой текст `raw`; необязательный `slot` с проверкой совместимости через Lua. Без слота добавляет в список предметов. |
| `pob_set_config` | Объект `values`: точные имена, типы и варианты из каталога `config`. |
| `pob_set_custom_mods` | Текст пользовательских модификаторов; заменяет прежний текст. Предположения явно раскрывайте пользователю. |
| `pob_tree_action` | Узел `id`, действие `allocate`, `refund`, `toggle`, `right` или `note`; `attribute`: 1 сила, 2 ловкость, 3 интеллект. Путь и зависимости определяет Lua. |
| `pob_tree_options` | Класс, восхождение, оружейный режим и набор дерева; точные ID из каталога и отчёта. |
| `pob_select_main_skill` | `control`: `groups` или `skills`, `id` из `snapshot.buildInfo`; выбирает оригинальным контролом Lua. |
| `pob_node_tooltip` | Свойства узла, маршрут и расчётные изменения из `AddNodeTooltip`. |
| `pob_check_build` | Подробный отчёт и необязательные цели `targets`, например `[{"stat":"Life","min":3000}]`. |
| `pob_export_xml` | Полный XML из `SaveDB`. Файлы автоматически не записываются. |

Каталоги отражают текущую ревизию данных репозитория, а не последнюю версию игры. Не угадывайте ID, восхождения, названия баз или варианты условий. Для поиска используйте игровые названия из каталога; подписи API на русском не переводят игровые идентификаторы.

## Полный цикл работы ассистента

1. Уточнить класс, основное умение, уровень, бюджет, доступные предметы и цель: карты или конкретный босс. Отдельно зафиксировать реалистичные условия боя.
2. Получить каталоги классов, камней, баз, слотов и условий. Найденные значения использовать буквально.
3. Создать сборку либо импортировать существующий XML. Новая сборка наследует **оригинальные настройки PoB по умолчанию**: они могут включать босса и выполненные квесты. Прочитать `config` и явно задать нужные условия.
4. Добавить основное умение и поддержки. Добавить предметы из исходного текста, указав слоты. Выбрать основную группу через список отчёта.
5. Найти узлы через каталог, посмотреть подсказку и назначить маршрут через `pob_tree_action`. Для выбора атрибутов задавать `attribute` явно.
6. Получить отчёт; проверить требования, предупреждения, слоты, камни и неподдержанные строки модификаторов. Изменить сборку и повторить расчёт.
7. Проверить цели по конкретным исходным показателям, экспортировать XML и повторно импортировать его. Сверить ключевые показатели и состав сборки.
8. Вернуть пользователю XML и подробное описание: дерево, камни/уровни, предметы, показатели, условия расчёта, предупреждения и неподтверждённые предположения.

Готовый исполняемый пример: [`assistant_example.py`](../tools/assistant_example.py). Он создаёт демонстрационную сборку для проверки API, а не рекомендуемый игровой билд:

```powershell
python -X utf8 examples/build_fireball.py --pob-dir C:/Tools/PoB-engine
python -X utf8 examples/build_fireball.py --pob-dir C:/Tools/PoB-engine --output C:/Builds/api-fireball.xml
```

Существующий файл пример не перезаписывает. XML подходит для открытия исходной программой и Flutter-клиентом.

## Что содержит отчёт

- `source: "original-lua"`, `snapshot` с версиями данных, классом, уровнем и селекторами основного умения.
- `stats`: все конечные скалярные поля `calcsTab.mainOutput`, а не только DPS/здоровье. Числа имеют исходные значения Lua. Таблицы и внутренние объекты не сериализуются; отсутствующее поле не означает ноль. Несериализуемые нечисловые значения и неограниченные числа пропускаются.
- `config`, `configPlaceholders`: установленные параметры и исходные значения-подсказки Lua. Пользовательские модификаторы — часть условий, их нельзя скрывать за итоговым DPS.
- `customMods`: исходные тексты пользовательских блоков и `unparsed` из `modLib.parseMod`. Нераспознанная строка требует проверки автора; разбор строки не доказывает достижимость эффекта в игре.
- `groups`: камни, ID, уровни, качество, состояние и `error`, если Lua его выставил.
- `items`: оригинальный текст, база, редкость и `unsupported` — строки, которые исходный разбор не распознал полностью. Наличие распознанной базы не доказывает корректность всех модификаторов.
- `slots`, `allocatedNodes`, `pointDisplay`, `sets`, `activeSets`, `notes`, `warnings` из оригинальной программы.
- `checks`: исходное значение и результат сравнения с каждой целью. Недоступный показатель даёт `actual: null`, `passed: false`; без целей `targetsPassed: null`.

Положительный `targetsPassed` означает только выполнение числовых целей. Он не отменяет предупреждения и не гарантирует легальность в игре, доступность предметов, цену, удобство управления или реальную выживаемость. Ассистент должен перечислить ограничения вместо заявления «сборка полностью проверена».

## Python API и подключение моделей

```python
from pob_poe2_mcp.api import BuildAPI

with BuildAPI(pob_dir="C:/Tools/PoB-engine") as api:
    classes = api.call("getCatalog", {"kind": "classes"})
    api.call("createBuild", {"name": "Моя сборка", "level": 90})
    report = api.check([{"stat": "Life", "min": 3000}])
    xml = api.call("exportBuild")["xml"]

# Уже открытая сборка окна PoB после установки Lua-моста:
with BuildAPI(mode="app") as api:
    report = api.check()
```

Для своего приложения с ChatGPT/Claude используйте [tools.json](../pob_poe2_mcp/data/tools.json) как описание инструментов: `name`, `description`, `inputSchema`. Приложение получает вызов инструмента от модели, проверяет аргументы, вызывает локальный API и возвращает результат модели. Сопоставление инструментов с Lua-методами находится в `pob_poe2_mcp/server.py:METHODS`; `pob_check_build` вызывает `api.check()`. Секреты провайдера хранит приложение-оркестратор, этот сервер их не требует. Не позволяйте модели передавать произвольный Lua или самостоятельно выдумывать показатели.

## Ревизии, ошибки и ограничения

Успех MCP возвращает `structuredContent: {revision, result}` и ту же информацию в текстовом блоке. Ошибка инструмента возвращает `isError: true`, `code`, `message`. Основные коды: `INVALID_REQUEST`, `INVALID_BUILD`, `STALE_REVISION`, `CALCULATION_FAILED`, `TIMEOUT`, `ENGINE_STOPPED`, `MESSAGE_TOO_LARGE`. Python API поднимает `EngineError` с полем `code`.

Клиент автоматически передаёт текущую ревизию. Lua последовательно выполняет команды, увеличивает ревизию после успешных изменений и откатывает неуспешное изменение через XML. Повторная загрузка может нормализовать XML: сравнивайте содержимое и расчёты, а не побайтовое оформление файла. В режиме `app` ручная правка окна тоже меняет ревизию: после `STALE_REVISION` заново прочитайте сборку. Импорт XML и создание новой сборки при несохранённых правках возвращают `UNSAVED_CHANGES`; открытый диалог — `APP_BUSY`. Ошибка подключения возвращает `BRIDGE_NOT_RUNNING`. После таймаута режим `engine` завершает дочерний процесс; режим `app` закрывает соединение, само приложение остаётся открытым.

Лимиты: сообщение 8 MiB, XML 4 MiB, текст предмета/модификаторов 64 KiB, каталог до 200 записей, группа до 12 камней, ожидание Lua по умолчанию 60 секунд. Эти ограничения транспорта не являются игровыми правилами. Процесс не записывает сборки, не запускает произвольные команды и не обращается к торговле или аккаунтам.

Редактирование группы/предмета по ID, полное управление наборами предметов/умений/условий, автоматическое сравнение альтернатив, share-коды, импорт аккаунта, торговля, источники всех вкладов расчёта и удалённый HTTP MCP пока не реализованы. Полный существующий XML можно импортировать/экспортировать уже сейчас; новые группы и предметы добавляются указанными инструментами.

## Проверки

```powershell
$env:POB_DIR = "C:/Tools/PoB-engine"
python -X utf8 -m unittest discover -s tests -v
```

Проверяются настоящий MCP stdio, каталог, создание, камни, предмет/слот, условия, модификатор, отчёт, числовые цели, экспорт/повторный импорт, ревизии и откат ошибочных изменений. Это проверка API на локальном Windows runtime, а не испытание готовой сборки в игре.
